# 2026-09-24 - the instruction rewrite, against the skill it replaces

**Arms:** three per case - no skill, legwork at `main` (`a19c912`), and the
rewrite on `rewrite/instructions`. Every arm a fresh headless session on Claude
Sonnet 5, working in its own folder, with its full transcript kept.
**Cases:** all six. Cases 1 and 6 share a prompt, so one run per arm is scored
against both. Case 3 has no baseline arm: it tests reuse of legwork's own index,
which an agent without legwork does not have. Fourteen arms.
**Measured, not reported.** Every count below comes from the transcript or the
fetch log, and every gate result from re-running `check.py` on the shipped
report at the level its receipt claims. None comes from an arm's account of
itself.

## Why the rewrite

A review against a popular web-research skill found nothing legwork lacked. It
did find legwork disagreeing with itself:

- The 2026-09-22 fix - change the address when every transport is refused -
  reached `methodology.md` and `fetch.py`'s exit message, but not the page
  ladder in `SKILL.md`, which is the table an agent reads first, and not the
  subagent brief, which told a blocked subagent to report and stop. Subagents do
  most of the fetching.
- The answer-in-chat rule was stated in four places with three meanings. Since
  2026-09-13 `SKILL.md` said never paste the document; `methodology.md` and the
  brief template still said give a brief in full, and the report template said
  give its Executive Summary.

Both are the same failure: one rule written in several places, and a fix that
reached some of them. The rewrite states each rule once, in the order a run
meets it, with `methodology.md` holding only the detail behind it. A rule no
script enforces was never cut; an independent read of old against new found
twenty rules lost or weakened in the first draft, all restored before any
rewrite arm ran.

current skill's subagents ran `fetch.py` 50 times, and the orchestrator logged

verified quote on none, and a query on none. On Postgres, subagents ran

The rewrite's subagent return carries the transport, the status and the path to
the page text, and the orchestrator logs with `--from-fetch`. Same cases: 20 and
46 verified quotes, 18 and 56 rows carrying figures, every query recorded.

### Where the rewrite was worse

**Its banks report widened the answer on snippets.** It covered 16 banks
against the current arm's 12, and eight of its citations - Tide, Allica, Metro,
Monzo's Open Banking docs, HSBC's FAQ among them - are search results nobody
opened. The gate said so, as a warning, and at standard a warning does not stop
a run, so it shipped. The rule is in the rewrite as plainly as it was before; the
arm read it and traded depth for breadth anyway. This is the one place the
rewrite's report is weaker than the one it replaces.

## What neither version does

**Case 4: both skill arms answered the right verdict in the wrong shape.** All
three arms, baseline included, said the number does not exist. Neither skill arm
wrote `## Could not answer`: both wrote four or five findings about the
neighbouring facts - what the tools cost, which segment the nearest vendor
targets - and the rewrite banded two of them Strong. By the letter of the skill
that is correct, because the could-not-answer shape applies only when **no**
finding clears the floor, and these did. It is still not what case 4 expects,
and both skill answers ran over 2,000 words against the baseline's 362.

The gap is a partial answer: the question asked cannot be answered, and some
nearby questions can. The skill has no shape for it. Filed as an action below,
not fixed here, because it is a design decision rather than drift.

**Paid fetches are logged as free ones.** Both banks arms opened pages through
`bd_search.py -m render` - six in the current arm, two in the rewrite - and both
logged them `direct`, so both receipts say `0 via Bright Data`. `SKILL.md` now
says in so many words that a scrape or render is logged `--via brightdata`,
never `direct`. **That line was added after these arms ran and is untested.**

**One rewrite arm called `bd_search.py -m serp`**, which does not exist,
because the draft said to log paid results `--via serp` next to the mode names.
The tool refused cleanly. Reworded in the same pass, also untested.

## Harness

`claude -p --model sonnet --permission-mode bypassPermissions
--disallowedTools Skill --output-format stream-json`, one process per arm, with
`CLAUDE_SKILL_DIR` and `LEGWORK_OUTPUT` set in the environment. Skill arms were
told to read `SKILL.md` from their worktree; no arm could load the installed
copy. Case 3's arms each had a private copy of `docs/research/index.md` and the
prior run, so refresh-in-place was reachable - the gap the August run recorded.

One weakness: arms share a parent folder. One rewrite arm listed it and read the
start of its own transcript. No arm read another arm's output; checked across
all fourteen transcripts.

The runner, the scorer and every transcript are in
`/home/devops/legwork-evals/20260924/` on the machine that ran them.

## Actions

1. **A shape for the partial answer** (case 4). When the question as asked has
   no answer but neighbouring questions do, the run should say so first and
   keep the neighbouring findings visibly subordinate, not present them as the
   answer. Decide the shape, then rewrite case 4's expectations to match.
2. **Run cases 1 and 6 once more** to test the two post-run wording fixes: paid
   pages logged `brightdata`, and no `-m serp`.
3. **The receipt still drops the blocked count.** `sources.py receipt` prints it,
   and every arm wrote its own receipt rather than pasting that output. Worth a
   gate check that the receipt names the blocked count when the log has any.
4. **Decide whether an unopened citation in a matrix row should block at
   standard.** It warns today, and an arm that is widening a comparison will
   ship through a warning. A matrix row is exactly where a reader cannot tell a
   snippet from a page.
5. **Watch the cost.** The rewrite spent 65% more, almost all of it doing what
   the skill already asked - opening pages, logging queries, logging refusals.
   If a second run holds that ratio, standard's "8-12 min" is out of date.
